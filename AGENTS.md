# Virtual Eye: notes for AI coding assistants

Read this before changing anything. It's for any assistant (Codex, Claude, Copilot...)
and for human contributors.

## What this is

An Android app (Expo / React Native) that helps blind and visually impaired people
understand their surroundings. It takes a photo about once a second, detects objects
and reads text **on the phone**, and speaks only what changed ("Car ahead, very close").
An optional Python server offers a bigger model.

Owner: RealHaroon (GitHub). Expo account: `haroon1nonly`.

## Layout

```
mobile/                      Expo SDK 54, React Native 0.81, New Architecture, expo-router
  app/index.tsx              Camera screen: detection loop, gestures, torch, speech
  app/settings.tsx           Settings (speech speed, verbosity); spoken feedback
  lib/announcer.ts           What to say each frame (only changes, priority order) [pure]
  lib/yolo.ts                YOLOv8 tensor decoding, NMS, input tensor layout     [pure]
  lib/ocrText.ts             Cleans raw OCR lines before speaking                  [pure]
  lib/onDeviceDetector.ts    TFLite pipeline: resize -> JPEG decode -> model -> yolo.ts
  lib/onDeviceOcr.ts         ML Kit text recognition (expo-text-extractor)
  lib/settings.ts            Settings store, saved to settings.json via expo-file-system
  lib/*.test.ts              Unit tests for the pure modules (Node's built-in runner)
  plugins/withMlKitOcrModel.js  Manifest meta-data: download OCR model at install
  assets/models/yolov8n.tflite  YOLOv8n, LiteRT export, input [1,3,320,320] NCHW,
                                output [1,84,2100], normalized xywh (see its README)
server/                      Optional FastAPI backend: YOLOv8m + EasyOCR, POST /detect
.github/workflows/ci.yml     Type-check, lint, tests on every push
```

"[pure]" files have no React Native imports so Node can test them. Keep it that way:
put new logic in pure modules and keep RN/native calls in thin wrappers.

## Commands (run in `mobile/`)

| Task | Command |
|---|---|
| Unit tests | `node --test "lib/**/*.test.ts"` (or `npm test`) |
| Type-check | `node_modules/.bin/tsc --noEmit -p .` |
| Lint | `node_modules/.bin/eslint app lib plugins` |
| Bundle check (offline) | `EXPO_OFFLINE=1 CI=1 node_modules/.bin/expo export --platform android --output-dir /tmp/x` |
| Build APK (cloud) | `eas build -p android --profile preview` (add `--non-interactive --no-wait` to just queue it) |
| Dev build | `eas build -p android --profile development`, then `npx expo start --dev-client` |

The app does **not** run in Expo Go (native TFLite and ML Kit modules).

## Gotchas

- **Local path contains `:`** (`/run/media/haroon/Local Disk (D:)/...`). That breaks
  `npx` and `npm run <script>` on the owner's Linux laptop ("tsc: not found"). Call
  binaries directly via `node_modules/.bin/...`. CI is unaffected.
- **Stale typed routes**: if `tsc` complains that a route like `"/settings"` isn't
  assignable, delete `mobile/.expo/types/router.d.ts` (gitignored, regenerated by `expo start`).
- **Don't change** `slug` (`VirtualEye-Exhibition`, tied to the EAS project) or
  `android.package` (`com.haroon1nonly.VirtualEyeExhibition`, lets new APKs install over old).
  The user-facing name is `expo.name` ("Virtual Eye").
- **Model layout**: ultralytics now exports TFLite via LiteRT (from PyTorch), so input is
  NCHW `[1,3,H,W]`. Older TF exports are NHWC. `inputLayoutOf()` handles both; don't
  hard-code. Exporting needs TensorFlow/LiteRT: do it in Google Colab, not locally.
- **Server mode**: only when `EXPO_PUBLIC_BACKEND_URL` is set in `mobile/.env.local`.
  If unreachable, the app falls back to on-device for 30 s, then retries.
  The server response keeps `text`/`warning` for old app builds plus `objects`/`ocr`.
- **Accessibility is the product.** Every control needs `accessibilityRole`/`Label`.
  The full-screen `Pressable` handles tap / double-tap / long-press and exposes the same
  as TalkBack `accessibilityActions`. Test with TalkBack on.

## Owner preferences

- **No AI attribution in commits or PRs.** No `Co-Authored-By: Claude`/AI trailers, no
  "Generated with ..." lines.
- **Limited mobile data.** Don't download large things (models, TensorFlow, Gradle/NDK,
  local Android builds) without asking. Prefer EAS cloud builds.
- **Python**: use the existing global env `~/.global_env` (shell alias `pyglobal`). Don't
  create venvs or pip-install. It has torch, ultralytics, cv2, numpy, fastapi, pillow;
  it does **not** have easyocr or any TFLite runtime.
- Commit on `main` with clear messages; the owner pushes (GitHub account RealHaroon;
  `gh auth switch --user RealHaroon` if a push gets 403).

## How behaviour was verified (reuse these ideas)

- YOLO decoding was checked against ultralytics on real tensors: run the `.pt` model in
  PyTorch on a 320x320 frame, dump the raw `[84, 2100]` output, decode it with
  `lib/yolo.ts` in Node and compare with `model.predict()`.
- The TFLite file's tensor shapes were read with a tiny FlatBuffer parser (no runtime).
- Native config was checked with an offline `expo prebuild --platform android --no-install`
  and grepping `AndroidManifest.xml` (back up `package.json` first; prebuild edits it,
  and delete `android/` afterwards).

## Roadmap (most useful first)

Done: on-device detection, change-only speech, gestures, settings, on-device OCR,
new icon, CI.

1. **Test on a real phone** and tune `lib/announcer.ts` numbers (`heartbeatMs`,
   `warningRepeatMs`, `CLOSE_AREA`/`NEAR_AREA`) from real use.
2. **Urdu voice**: `expo-speech` with `ur-PK` where available, translated phrases
   (keep phrase building in `announcer.ts`; add a language setting).
3. **PKR currency recognition**: needs a small custom detection model trained on photos
   of Pakistani notes (e.g. YOLO trained in Colab), run alongside the COCO model.
4. **SOS**: long-press is taken (repeat). Use a shake or a settings-configured contact;
   share location via SMS intent.
5. **AI scene description on request**: send one photo to a vision LLM for a rich
   description. Optional, needs internet and an API key (never ship a key in the app;
   proxy it through `server/`).
6. **Smoother capture**: `react-native-vision-camera` frame processors instead of
   `takePictureAsync` (faster, less battery). Check Reanimated/worklets compatibility.
7. **Real distance**: depth model or ARCore depth instead of box-area thresholds.
8. **Shrink git history**: `.git` is ~150 MB from old `.pt` files. Needs
   `git filter-repo` + force push; coordinate with the owner first.
